# Synology Calendar 日历

沿用 [NAS 共用流程](../synology-nas/SKILL.md)。先用 `nas_apis(query="SYNO.Cal.")` 和 `nas_describe` 核对已安装的 Calendar 和版本。当前没有 `calendar.*` 预设配方；使用 `nas_request`，不能编造配方名。此工具连查询也需要先预览，再显式 `execute=true` 且写开关开启。

## 查看安排

- 先列出当前账号可访问的日历，再选用户指定的日历 ID；名称重复时确认对象。日历和待办列表分开，不能从 Note Station 的待办接口取日历待办。
- 把“今天”“明天”“下周”等解析为 Octop 配置的服务端时区；明确日期范围，转换为目标接口要求的日期或时间戳。显示时间注明时区；已有事件按其事件时区理解，不擅自修改时区设置。
- [只读请求参考](references/queries.md) 给出已有客户端使用的查询结构，调用前仍须核对当前版本。按查询结果读取事件详情，保留重复事件的单次实例身份，不能把重复项全部当成新事件。

## 创建、调整与删除

先明确日历、标题、开始和结束、时区、全天或重复、提醒和参与者；只追问无法从用户要求及已有事件中确定的必要信息。只有日期的全天事件不能擅自变成 UTC 零点的定时事件。

写入前核实该 Calendar 版本的可靠参数。旧版和新版事件写入格式不同，不能只把 API 版本改大；本技能不提供未经验证的写入模板。编辑前读取现有详情及版本要求的并发标记（例如 `dav_etag`），保留未修改的提醒、参与者和附件。

重复事件必须明确改单次还是整个系列；邀请可能向参与者发送通知，预览要列出影响。通过 `nas_request` 先预览，按具体授权执行，之后重新读取目标。超时先查询，不能盲目重建事件；不能把 API 预览、生成的草稿或 Octop 定时任务说成“已加入群晖日历”。
